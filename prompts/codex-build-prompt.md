한의원 진료실/데스크에서 쓰는 "로컬 차팅 보조 도구"를 만들어줘. 개인정보를 먼저 걸러낸 뒤, API로 보낸 마스킹된 정보와 증상을 AI가 차트 형식에 맞게 항목별로 정리하고 EMR에 붙여넣을 수 있는 형태, React + Vite로 프론트엔드를 구성하고, 전체가 로컬에서만 실행되는 구조로 만들어줘.

## 핵심 원칙 (반드시 지킬 것 — 모든 기능 구현 시 이 원칙을 최우선으로)
1. 환자 개인정보(이름, 연락처, 주민번호, 주소 등)는 어떤 경우에도 외부 API로 전송되지 않는다. 마스킹 처리 후의 텍스트만 전송된다.
2. 음성 데이터도 어떤 경우에도 외부 서버로 전송되지 않는다. 브라우저 내장 음성인식(Web Speech API)은 사용하지 않는다.
3. 마스킹된 텍스트는 사람이 직접 확인하기 전에는 최종 전송되지 않는다 — 반드시 명시적 승인을 거친다.
4. 로컬 서버는 127.0.0.1(localhost)에서만 바인딩되어야 하고, 0.0.0.0으로 열려서 같은 네트워크의 다른 기기에서 접근 가능해지면 안 된다.
5. 로컬에 저장되는 환자 기록도 원본 미마스킹 텍스트가 아니라, 마스킹·검토·승인된 내용만 저장한다.
6. 새 기능을 추가하더라도 이 원칙들이 깨지지 않는지 항상 우선 검토한다.
7. 음성 녹음에서 증상과 상담과 거리가 먼 사담, 잡담은 지우고 차팅 형식으로 분류한다.

## 전체 흐름
1. [환자 조회/신규 등록] 환자 ID로 기존 환자 검색 → 이전 방문 기록 불러오기, 또는 신규 환자 ID 발급
2. [음성/텍스트 입력] "증상" 입력창 옆 녹음 버튼으로 음성 녹음 → 로컬 Whisper 모델로 텍스트 변환 → 입력창에 삽입 (직접 타이핑도 가능)
3. [로컬 마스킹 필터] 입력 텍스트에서 개인정보로 의심되는 항목을 로컬에서 규칙 기반으로 탐지 및 마스킹
4. [전송 미리보기] "실제 API로 나갈 텍스트"를 마스킹 적용된 상태로 화면에 표시
5. [고위험 식별자 경고] 확신도 낮게 탐지되었거나 놓쳤을 수 있는 고위험 패턴은 빨간 경고 카드로 별도 표시
6. [승인 게이트] "마스킹된 상태로 전송을 승인합니다" 체크박스를 체크해야만 전송 버튼 활성화. 체크 전에는 API 호출 자체가 불가능
7. [API 호출] 승인된 텍스트만 Claude API로 전송, 한의원 표준 차트 항목(주소증/현병력/문진 소견/설진·맥진/진단/처방 및 향후 계획 등)에 맞게 구조화
8. [결과 출력 및 저장] 항목별로 정리된 차트 표시, EMR 붙여넣기용 복사 버튼 + 로컬 암호화 DB에 저장
9. [다음 방문 시] 같은 환자 ID로 검색하면 이전 방문 기록들을 불러와서 참고 가능

## 음성 인식 상세
- 로컬 Node 백엔드에 Whisper 기반 로컬 음성인식을 붙여줘 (whisper.cpp 서브프로세스 또는 faster-whisper를 별도 로컬 프로세스로 띄워서 로컬 API로 노출)
- 프론트엔드는 마이크 권한을 요청하고, 녹음된 오디오를 로컬 백엔드(127.0.0.1)로만 전송
- 백엔드는 변환된 텍스트만 프론트엔드로 반환
- 모델 크기는 기본 base/small로 시작, 설정 파일에서 medium 등으로 조정 가능하게 (사양 낮은 컴퓨터 고려)
- 변환된 텍스트도 예외 없이 마스킹 필터 → 전송 미리보기 → 승인 게이트를 거친다

## 마스킹 필터 상세
- 필터 로직은 별도 모듈로 분리 (예: src/lib/pii-filter.ts). 이 필터를 통과하지 않은 텍스트는 어떤 코드 경로로도 API 호출 함수에 도달할 수 없는 구조로 짜줘
- 탐지 대상: 한글 이름 패턴(2~4자 성명, "환자명" 근처 문맥), 전화번호 형식, 주민등록번호 형식, 주소로 보이는 패턴
- 탐지된 항목은 [환자명], [연락처] 같은 코드명 토큰으로 치환
- 확신도 낮게 탐지된 항목은 자동 마스킹하되, "고위험 식별자" 경고 카드에 별도로 나열해서 사람이 직접 재확인하게 함

## 로컬 환자 기록 저장 상세
- SQLite + SQLCipher(암호화)를 사용한다 (예: better-sqlite3 + sqlcipher 조합, 또는 동급의 암호화 SQLite 라이브러리)
- DB 파일은 로컬 경로(예: data/clinic.db)에 저장, .gitignore에 포함
- 암호화 키는 코드에 하드코딩하지 않는다. 최초 실행 시 사용자가 마스터 비밀번호를 설정하고, 이후 실행마다 비밀번호 입력으로 DB를 잠금 해제
- 환자 ID는 실명·생년월일 등에서 유추 가능한 값이 아니라 무작위 UUID으로 발급
- ID와 실명의 매핑 정보도 암호화된 DB 내부에만 존재 (별도 평문 파일로 남기지 않음)
- 환자 ID 검색 화면: 신규 환자는 새 ID 발급, 기존 환자는 검색 후 선택
- 이번 방문 기록 저장 시 마스킹·승인된 내용만 저장 (원본 미마스킹 텍스트는 저장하지 않음)

## 분류해야 하는 초진 차트 형식
- C/C
- 계통 문진(소화, 대소변, 수면, 한열, 진액, 정신, 흉부 복부 두부 증상 등)
- O/S
- Mode of O/S
- P/I
- 과거력 및 가족력
- 타병원 진단 및 기록
- 변증
- R/O
- Dx
- 검사 결과
- Plan

## 분류해야 하는 재진 차트 형식(SOAP)
- Subjective: 환자가 말하는 주관적 자료
- Objective: 객관적 자료(시청각적 정보, 검사결과 등)
- Assessment: 평가 및 진단
- Plan: 치료계획

## UI 요구사항
- 최초 실행 시 마스터 비밀번호 설정/입력 화면
- 환자 검색/신규 등록 화면: ID 입력 또는 "신규 환자" 버튼
- 이전 방문 기록이 있으면 방문 일자별로 목록 표시, 클릭하면 해당 차트 요약 확인 가능
- "증상" 텍스트 입력창 (여러 줄) + 옆에 마이크 아이콘 녹음 버튼. 녹음 중엔 버튼 빨간색 + "녹음 중..." 표시, 종료 후 "변환 중..." → 완료되면 텍스트 자동 삽입
- "전송 미리보기" 카드 (헤더에 "실제 API로 나갈 텍스트" 명시)
- 고위험 식별자 감지 시에만 빨간 경고 카드 ("⚠ 고위험 식별자 N건 — 확인이 필요합니다" + 감지 항목 리스트 + 승인 체크박스)
- 정리된 차트 결과 (항목별 카드/섹션 구분), 복사 버튼, 저장 버튼
- 폰트: Pretendard (CDN: https://cdn.jsdelivr.net/gh/orioncactus/pretendard/dist/web/static/pretendard.css)
- 톤: Apple 스타일의 흰색과 파란색 계열, 과한 색감 지양

## 기술 스택
- React + Vite (프론트엔드)
- Node 로컬 서버 (API 프록시 + Whisper 연동 + SQLite DB 접근), API 키가 프론트엔드 번들에 절대 노출되지 않도록 서버사이드에서만 외부 API 호출
- API 키는 .env로 관리, .gitignore 포함
- 로컬 실행 스크립트 run.sh(Mac) / run.bat(Windows) — 더블클릭 시 의존성 설치 확인, Whisper 모델 최초 1회 다운로드, npm run dev 실행, 브라우저 자동 오픈

## 검증 요청
빌드 완료 후 아래를 직접 확인해서 알려줘:
1. 마스킹을 거치지 않은 원본 텍스트가 API 호출 함수 어디에서도 참조되지 않는지 코드상 확인
2. 로컬 서버가 127.0.0.1로만 바인딩되어 있는지 확인
3. 체크박스 미승인 상태에서 전송 버튼 클릭 시 API 호출이 실제로 발생하지 않는지 확인
4. 녹음된 오디오 및 그 처리 과정에서 로컬 밖으로 나가는 네트워크 요청이 없는지 확인 (개발자 도구 Network 탭 기준)
5. DB 파일(data/clinic.db)이 실제로 암호화되어 있는지 확인 (평문 텍스트 편집기로 열었을 때 내용이 읽히지 않아야 함)
6. 마스터 비밀번호 없이 DB 파일에 직접 접근했을 때 데이터가 복호화되지 않는지 확인
